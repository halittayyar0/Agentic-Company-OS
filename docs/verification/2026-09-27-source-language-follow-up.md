## Interface inventory limits

A temporary TypeScript AST traversal from `App.tsx` visited 316 source files and found 25 literal JSX-text/label candidates. Sixteen were in the old `components/model-picker.tsx`; the only incoming reference in the current source is a **type-only** `ModelSelectionValue` import. Active new/detail screens use `components/agent/agent-model-picker.tsx`. Treating every file import as a rendered component would have falsely reported this legacy picker as an active untranslated screen.

The other literal candidates were product names, keyboard notation, a configuration assignment, a time-zone identifier, units/version notation and a multiplication sign. This narrow check does not cover strings inside expressions, generated text, dynamic error paths, assistive output or server-authored content. It cannot establish complete translation. Legacy Company Floor/dispatch/canvas components also contain Turkish strings but have no incoming component imports in the current frontend; their presence is recorded separately from reachable routes.

## History still needs a product decision and implementation

The API already exposes bounded cursor pagination for activities, agent messages, task subtasks and task events. Several current views consume a single bounded window: Computer activity requests 20 records; Expert statistics sample 200 activities/messages; delegation conversation caps its task/message window at 200. The interfaces label these windows, which prevents a false claim of full history but does not provide older-history browsing. The final route audit must decide where explicit continuation belongs, preserve source ordering and recoverable errors, and retain durable request identities when defining output retention. Do not silently truncate history and call it complete.
