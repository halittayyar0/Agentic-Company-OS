# Expert configuration checkpoint — 27 September 2026

This records the local Windows working tree using Node 24.19.0. Existing work is preserved. This is a development checkpoint; Goal 7 and the broader release review remain active.

## Changes

- Expert detail has seven selected-language packs for its profile frame, saved model, instruction and portrait editing, permissions, archive/restore, assigned tasks, sampled statistics and recovery. The model picker reuses the localized New expert catalog. Names, custom roles, task text, instructions, catalog IDs/descriptions and event summaries retain their original content. The former event-summary rewrite is removed.
- The responsive layout uses grouped settings, semantic theme colors, 44px controls, native checkbox labels, keyboard-operated tabs, and Arabic direction. A dialog initially focuses Cancel and returns focus to the originating control or a usable page control. The UI distinguishes saved permissions/model choices from actual running work and provider availability.
- Instruction drafts and locally prepared portraits survive record polling and tab changes. Cached records remain visible after read failures. A stale configuration or unconfirmed write blocks another submission until a successful manual refresh; the preview/draft is retained for comparison. A missing configuration version makes server-changing controls read-only. Drafts are only in page memory and are lost on navigation or reload.
- Detail GET and configuration/portrait mutations return an opaque `configVersion`. UI saves send it as `expectedConfig`; the API compares under the agent row lock before changing state. It is a content hash, not a monotonic revision: identical restored configuration has the same hash. Heartbeats, leases and current activity are excluded. Legacy API callers can omit it and therefore do not receive this stale-edit protection. Avatar reset carries it in the query. No database migration is added.
- Portrait upload/reset now lock the agent before its portrait row. Upload preparation keeps the existing local image pipeline: PNG/JPEG/WebP, 5 MB input, a 40-megapixel accepted-resolution limit checked after decoding, and at most 64 KB stored output. The original image is not sent to an image service. Unknown persistence retains the preview rather than claiming a rollback or requiring reselection.
- Explicit instruction saves mark the instruction custom. Manual mode requires a nonblank model ID; automatic mode clears the old ID. The UI requires a connected, tool-capable catalog choice, while API clients can still supply custom IDs. This is not a provider-access guarantee, and an already-running request keeps its model.
- Restoration enforces the active-agent capacity under the existing runtime-control lock and returns an inactive expert to idle. Previously blocked tasks remain blocked. Archiving retains the existing in-flight approved-action fence and revokes unused capabilities for its open work. The root host control requires the server-managed root marker in addition to the displayed hierarchy; backend authority and exact human approval remain authoritative.
- Statistics explicitly describe their maximum 200-event/200-message sample. Counts are not labeled as lifetime totals, successful operations or costs. Artificial goal rings are removed. Model shares use sampled agent replies as the denominator, including replies without a model ID; terminal/file event text is preserved.
- Root-test concurrency now defaults to two file processes, with a validated `TEST_CONCURRENCY` override from 1 through 8. Each database integration file can start an independent PGlite runtime; using the CPU-count default exhausted native memory in a full rerun. This changes test scheduling, not application-worker concurrency.
