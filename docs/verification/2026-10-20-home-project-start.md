# Recover the first project from Home

## User outcome

Home now uses the same durable project-start protocol as New project. A lost
response retains the request identity, original brief and selected approach.
Checking reads its outcome; a missing receipt permits only explicit replay of
the identical request. A saved created receipt opens the existing project.

The first browser regression failed against the preceding production build:
Home's POST had no request ID. The new cases cover all seven selected languages
at 320px in both themes, reload, later edits, refused storage, missing and wrong
receipts, cross-composer recovery, failed module/language downloads and a late
acknowledgement after navigating away.

The browser adapter reuses the existing server transaction, receipt validation,
mounted-response fence and localized recovery controls. No database migration,
permission change, automatic replay or model request is added. The default
single finite job and existing-agent approach remain unchanged.

## Focused development evidence

- The complete seven-file browser selection passed **111/111**, no retries or
  skips. After the final seven-language control-load error wording, the complete
  Home recovery file passed **21/21**, again with no retries or skips. These
  scopes overlap and must not be summed. They use controlled API responses,
  rather than claiming physical-phone or genuine-model acceptance.
- English dark and Arabic light recovery screenshots at 320px were inspected.
  The submitted source text remains unchanged, controls wrap, keyboard inspection
  works, and the documents do not overflow horizontally.
- Existing request/draft and real HTTP creation/policy modules passed **30/30**,
  with no failures or skips. These establish server replay, policy and capacity
  boundaries separately from the controlled browser cases. Later bundle/source
  ownership checks passed **15/15**; the sets have separate scopes.
- Full workspace typechecks, production build, formatting, all-dependency audit
  (zero reported vulnerabilities) and production license policy passed in the
  development worktree. Matching-commit CI and native archive acceptance remain
  separate publication gates.
- Independent review found and corrected a bundle-accounting guard: both the
  route and split pre-existing language loader now require exclusive,
  hash-verified compiler source ownership. A valid hash with an unrelated
  co-owner is rejected. Final review found no remaining important issue.

## Bounded loading and measurements

The Home adapter loads separately. Only the selected existing recovery language
pack is used. Its bytes remain inside the original recovery **12KB raw / 5KB
gzip** cap. The existing language loader can now be shared: the original route
and that same loader are measured together once, under the unchanged **1200 raw /
500 gzip** route-wiring cap. No vendor, API, CSS, unrelated source or duplicated
credit is allowed. All original base, total, feature and per-route limits remain
unchanged; the complete actual bundle check passed.

Earlier failed loading-layout measurements are retained as development
observations. Broad lazy loading of the entire Home composer was rejected
because it moved unrelated ownership; it is not part of this change. The final
solution keeps the existing page structure and validates the exact split source
scope. The source/UI test census adds four source checks and 21 browser cases;
all existing named platform skips remain unchanged.

## Limits and next work

Recovery is per browser tab, retains the submitted brief in session storage and
is not a cross-device inbox or backup. Separate new request identities remain
separate jobs. A created workspace is not evidence that its agent completed the
work. Checking does not stop a job that is already running.

The matching release's qualification records must establish refreshed platform,
security, source, browser, native-installation and public-download evidence before
publication. This development checkpoint does not qualify a new package,
24-hour operation, general model quality or physical phone access.

The next useful journey improvement is an explicit one-off/recurring choice in
Home, which currently always submits a finite job. It should reuse the existing
scheduler and recorded interval without guessing or silently changing recurrence
from the brief.
