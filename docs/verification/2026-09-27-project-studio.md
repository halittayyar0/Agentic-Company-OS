# Project Studio frame and recovery — 2026-09-27

Goal 7 remains active. The previous conversation checkpoint is historical evidence; this checkpoint covers the next changes to the project frame, navigation, team overview, delivery records and stop confirmation.

## Changes and design review

- The selected language now covers these controls in Turkish, English, German, Russian, Simplified Chinese, Traditional Chinese and Arabic. Stored project titles, briefs, roles, activity text, model identifiers and delivery content remain original source text. The top summary uses recorded state, reported progress and counts of loaded child tasks. It no longer presents an absence of visible errors as verified delivery. Detailed trace remains available under Plan and trace.
- Apple HIG principles are applied to the web interface. `alerts.md › Content` says “be direct, and use a neutral, approachable tone”; the stop dialog explains the project/child-work scope and retained external effects, focuses Cancel initially, stays open during submission, and reports uncertainty inline. `loading.md › Best practices` says “Show something as soon as possible”; refresh failures preserve the loaded project, conversation draft and records, with a last-retrieved timestamp and explicit retry. `layout.md › Visual hierarchy` informs grouped controls, reading order and space for labels. The replacement record summary removes the cramped connector lines and truncated stage names found in the phone captures.
- Project tabs use the shared Radix tabs through the canonical `ProjectWorkbenchTabs` adapter. Workspace, plan, meetings, team and delivery selection persist in the URL while retaining other parameters/fragments. Back, Forward and reload restore selection. Arrow navigation follows Arabic direction; Home/End and tab/panel labels remain associated. Primary navigation/confirmation targets are at least 44px. The workbench uses the route's vertical scroll owner, with visible horizontal tab scrolling.
- A failed project refresh preserves the last successful view and blocks new conversation, stop and answer submissions through this page until refreshed. Failed roster/member/subtask/activity reads identify the unavailable context and have a retry. Unavailable child-task or activity snapshots do not become zero counts or empty lists; a successful empty response remains a separate state. Delivery records preserve loaded results on refresh failure; the bounded view shows the newest 80 loaded records in reverse chronological order and states the window limit. The model summary uses the observed `lastModelId`, without presenting a configured model as an observed execution.
- Stop requests save a local uncertainty marker before dispatch, block duplicate submission and never automatically replay on reload or GET recovery. Storage failure sends no request. A read can show the current terminal state but does not attribute that state to an earlier request. If work remains active, another stop requires a fresh read and a separate confirmation. The existing server cancellation is atomic for the root and active descendant tasks and refuses cancellation while an approved action owns a task lease; it is unchanged here.

The resume transaction checks the blocked reason but neither an exact question identity nor whether the owner still matches the agent locked from the earlier read. The next answer-flow pass must expose the actual reviewed question, bind the answer/receipt to it, revalidate ownership and test delayed resends after a later question. The existing test named “exact user_input wait” covers the blocked-reason gate, not exact-question binding.
