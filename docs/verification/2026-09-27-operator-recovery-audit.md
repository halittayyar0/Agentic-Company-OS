# Operator recovery — historical source audit

This records the gaps found before operator recovery was implemented. Its former current-state findings are historical. The [new implementation and verification checkpoint](./2026-09-27-operator-recovery.md) covers the receipt protocol, effect guards and seven-language recovery; use the [release audit](./2026-09-27-release-readiness.md) for current readiness. Goal 7 remains active.

## Verified current behavior

| Surface              | Current source                                                                                | Gap and user effect                                                                                                                                                                                                                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Terminal request     | `components/vm/terminal-panel.tsx`, `lib/terminal-session.ts`                                 | A local UUID is saved with the command, but the POST sends only command and authority. After a lost response, the browser cannot query the server by that identity. Acknowledging the local hold does not establish whether repeating the command is safe.                                                         |
| Browser request      | `components/browser/use-browser-workbench.ts`, `lib/browser-workbench.ts`                     | Local metadata identifies the pending action; navigation/input/control use the existing server protocol without that browser-generated identity. A later screenshot is an observation, not an exact action receipt.                                                                                                |
| Operator activity    | `artifacts/api-server/src/routes/vm.ts`, `beginOperatorActivity` and `finishOperatorActivity` | Activity uses a process-local session/sequence. Database logging errors are caught, and the caller can continue to the effect. It is an audit trail, not durable admission or deduplication.                                                                                                                       |
| Split browser worker | `artifacts/api-server/src/lib/runtime-control-api.ts`                                         | Runtime command metadata is durable and distinguishes queued/dispatched/unknown outcomes. Its server-created command ID is not the browser's request identity. Pending payloads/results are carried through process memory and encrypted envelopes; there is no operator-facing original-request receipt endpoint. |
| Privacy boundary     | `docs/browser-workbench.md`, `runtime-control-crypto.ts`                                      | Existing browser metadata excludes typed input, URLs, screenshots and private leases. A recovery design must preserve this boundary and must not mistake an old lease for current authority.                                                                                                                       |

Paths without a leading `artifacts/` above are relative to `artifacts/agentic-company-os/src/`.

## Required acceptance for the next implementation

1. Persist an authenticated, strictly scoped operator request identity before admitting a side effect. A database admission failure must dispatch nothing. Define a canonical binding for request kind, agent, authority and exact input, without exposing commands, input text, URL credentials or private leases in receipts/logs.
2. A matching repeated request must never create a second execution. Concurrent API instances, changed input under an accepted identity, owner expiry, server restart and worker replacement need explicit behavior and tests. A UI mutex alone is insufficient.
3. Provide an authenticated exact read that works independently of an activity-list window. Reads must not allocate a browser, refresh ownership, dispatch an effect, revive an expired owner or mutate an uncertain request into success.
4. Preserve uncertainty across the actual effect boundary. A lost HTTP response, post-effect screenshot failure or missing worker acknowledgement is not proof of failure. A receipt for completed execution is not proof that every external effect can be reversed.
5. Bind completion to the original accepted owner and identity. Stale completion must not erase a newer local request or operate on a replacement browser session. Emergency stop remains authoritative before dispatch and between queued steps.
6. Define which result fields can be recovered, their size/retention/privacy limits and the behavior after key rotation or missing output. Do not silently claim the full terminal output or browser capture is recoverable if only metadata is retained.
7. Add seven-language read/review/unknown/error states, original-source display, reload recovery, exact scope checks, cancel-first controls and focus restoration. Old local records without a server identity need an explicit legacy-unknown path, never an invented accepted ID.
8. Verify source/API fault cases and browser interactions, regenerate and check the API contract, migrate a clean local store, then run full suites on the final artifact. Native PostgreSQL and split-process/container acceptance remain separate until actually exercised.

No implementation decision about storing terminal output, introducing a key, or changing existing request compatibility is implied by this audit. Those choices require a concrete design against the existing server and worker boundaries. No software, remote service, credentials or publication were changed.
