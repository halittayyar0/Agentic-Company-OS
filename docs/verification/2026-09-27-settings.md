# Connections and recovery checkpoint — 27 September 2026

This records the local Windows working tree with Node 24.19.0. Existing changes are preserved. It is a development checkpoint, not a published release or a complete Goal 7 claim.

## Changes

- Connections/Settings has seven independently loaded language packs: Turkish, English, German, Russian, Simplified Chinese, Traditional Chinese and Arabic. Preferences, key handling, model-test consent, errors and unknown outcomes, catalog search and server-operation guidance are covered. The display follows the device theme by default, reflects changes made through the shell and supports RTL. Model names, IDs and original descriptions are preserved; the former price-text rewrite is removed.
- Provider status distinguishes saved application credentials, environment credentials and missing keys. Presence is not presented as a successful connection. Removing a saved key explicitly explains environment fallback and in-flight requests. Storage guidance distinguishes a plaintext local server file from encrypted shared database state; a saved revision does not imply all workers have applied it.
- Every UI save carries the reviewed revision. The local writer compares and advances its revision inside its existing serialized atomic-write path; split storage compares under a database row lock. Legacy callers can still omit the revision. Combined-mode coordination covers one API process, not multiple processes writing the same file.
- Unknown persistence or post-commit refresh outcomes retain the in-memory draft and block another submission until a successful manual refresh. Conflicts require the same review. A response loss is not treated as rollback. Inputs and tests cannot overlap an ongoing save. This is not a durable browser draft: navigation or reload clears it, and this page does not store keys in browser storage.
- A model test requires an explicit catalog selection and confirmation. It sends a fixed short prompt, requests at most 10 output tokens, waits at most 20 seconds in the completion wrapper and disables SDK retries. Emergency stop is checked before dispatch. A nonempty reply must match the provider and unchanged credential revision; upstream text is not returned. Results are historical and model-specific. Provider processing or charges may continue after a timeout; the test is not a spending cap or an in-flight cancellation guarantee.
- The Settings routes return generic read/save/test errors without echoing upstream details. Short credential previews of up to 12 characters are entirely masked; the old 11-character preview could reveal the whole key. Local save-and-apply ordering is serialized. Operational rate limits are per client/process, not distributed.
- The shared render-error fallback has small bundled messages in all seven languages and does not require LocaleProvider. It focuses the recovery heading, works at phone width and offers full reload for failed lazy modules. It no longer claims data were preserved; production caught-error logging omits raw error objects and stacks. Developer details remain available only in development builds.
