# Localization and language contributions

The first-run chooser and Settings support `tr`, `en`, `de`, `ru`, `zh-CN`, `zh-TW`, and `ar`. The browser saves the choice under `acos.locale.v1`; after operator authentication the same enum is written to the authenticated `/api/settings/locale` endpoint. It is stored in the shared, gitignored `data/workspace-locale.json`, so API and worker processes use the same language for **future** agent turns. The model may still make mistakes; a language directive is not a translation guarantee.

Current localized surfaces: first-run choice, sign-in and auth failure screens, navigation, theme and sign-out controls, command search, reusable close and search controls, shared loading/connection status, language settings, 404, shared relative dates, Home, the quick project composer, the Projects list, the full New project form, and the shared emergency stop control. Home includes its loading/error states, examples, validation, task status badges, and persisted work-approach text. The Projects list includes filters, search, owner labels, status, progress, and empty/loading/error states. New project includes field validation, mode/priority/cadence choices, empty team and security stops, and success/failure feedback. The emergency stop translates its confirmation, reason, failure, recovery, and active banners; if its selected language file fails, the control remains operable with English safety copy. Page and emergency-control language packs are loaded only when selected; the bundle check enforces both a selected-language transfer budget and aggregate pack budgets. New application-authored output from the 32 runtime tools uses the selected execution language, as detailed below. Stored custom names, roles, historical records and external provider/process content remain in their original language. Treat the other locales as **partial** in this alpha release. Do not describe them as complete until every route, state, and flow has been reviewed by a speaker of that language.

The Expert directory is also localized in all seven languages, including template summaries, department names, filters, search, pagination, counts, and initial/empty/error/stale states. Search matches both localized explanations and stored names/roles; custom values, agent names, and current work remain in their original language. A failed refresh identifies the last loaded roster, while an initial failure does not imply an empty team. Directory and sign-in copy load only for the selected language. An unavailable sign-in language file keeps the workspace closed and offers a reload; language files contain no authentication or operator data.

New expert creation also translates its form, role names, validation, permissions, model selection, and success/failure feedback in all seven languages. Suggested identities use the selected language; edits, custom instructions, existing agent names, and canonical department keys are preserved. All 15 managed role playbooks and their shared evidence/approval rules now have complete authored catalogs in the selected language. The preview and create request use that exact locale; a stale or unavailable managed catalog blocks creation. Custom instruction bytes and provider catalog descriptions remain source content. Inline language changes retain edited names, permissions and custom instructions. A failed surface-language download can return to the previous language without discarding the form. Manual selection requires a successfully loaded catalog entry with a connected provider and agent-tool support; a failed refresh blocks submission until the catalog can be checked again. This UI check cannot guarantee that a provider will remain available for a later agent turn.

The shell loads only the selected language pack initially. The small first-run chooser and loading/recovery messages remain available before a pack loads; an initial failed shell pack offers a localized reload while authentication and workspace requests remain unopened. During a later language change the current tree remains mounted until the new shell pack is available, and cancellation prevents a late download from committing. A failed change retains the old language and offers recovery without dropping the current form. Preference writes from the same page are serialized across effect cleanup and component remount, so a delayed older write cannot overtake a newer queued selection. Obsolete queued selections are skipped; an earlier failed request does not stall the latest one. Separate browsers remain independent writers of the shared preference. Turkish shared-component fallback copy remains bundled for standalone previews. These changes retain the existing total transfer budgets.

Arabic navigation opens from the right and keeps keyboard focus inside the phone menu until it closes. Shared command search preserves the opener's focus on dismissal and remains scrollable when the viewport height is reduced. The `/activity` bookmark redirects to `/operations`, preserving its query and fragment and focusing the destination heading once.

## Authored role and workforce instructions

`artifacts/api-server/src/lib/agent-template-localization.ts` is the shared catalog boundary. Canonical Turkish `agent-templates.ts` owns keys, authority and permissions; six `agent-template-locales/` files own translated text only. Results are detached copies. `GET /api/agent-templates?locale=...` and agent creation validate the seven-locale enum, defaulting omitted legacy values to Turkish. An explicitly supplied `systemPrompt` is custom even when a template key is present; its whitespace and Unicode are preserved. This prevents new custom records from being replaced at startup, but cannot restore content already lost in older installations.

Startup reads the saved workspace locale for stock prompts. Future managed chat/task turns select that current workspace language even when first-run selection happened after seeding. Custom and installed prompts remain unchanged, as do existing agent identities and historical messages. Workforce orchestration keys, hierarchy, template versions and permission boundaries are independent of translated labels. See the [authored instruction checkpoint](./verification/2026-09-27-authored-agent-locales.md) for coverage and remaining full-release/native-language gates.

## Current transfer budgets

The executable policy in `scripts/src/check-bundle-budget.ts` bounds shared code
plus the largest selected pack for each localized surface at **1,345,000 raw /
398,500 gzip bytes**. Code outside the new skill-library route and draft helper
still has the prior **396,000 gzip byte ceiling**. The library itself is limited
to **8,000 raw / 2,500 gzip bytes**; aggregate, per-asset, media and language-family
limits also apply. Historical feature checkpoint figures above are not current
release results. See the [current verification record](./verification/2026-09-27-release-readiness.md)
for the latest measured build and the remaining release gates.
