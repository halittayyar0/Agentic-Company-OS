# Accessible, efficient autonomous work

## Intent and decisions

Deliver a public, installable product for a person with basic technical knowledge. Small jobs start with one economical agent. Larger jobs may delegate bounded independent work. Recurring responsibilities sleep between executions, retain state and stop spending when their budget is exhausted. Completion must be supported by persisted results. Preserve all seven languages, permissions, custom tools and source-workspace functionality.

The user explicitly requested autonomous implementation, tests and publication without repeated approval questions. Execute inline, with a final independent review. Reuse the clean publication checkout; leave the operator's unrelated working tree untouched.

## Distribution

A public static start page explains installation, requirements, model costs, examples and boundaries. Each installation remains a separate single-operator workspace. A public unauthenticated shared host with shell access is not a substitute for tenancy. No mandatory paid hosting. Prefer a prebuilt container path to avoid compiling on small machines; retain native setup. Never silently purchase infrastructure or redistribute credentials.

## Execution economy

Automatic execution begins with an economy route regardless of organization depth. Escalation depends on observed difficulty, not a CEO title. Explicit model choices and free-only boundaries continue to win. Include concise task instructions to reuse agents, delegate only independent deliverables, read relevant skills on demand and avoid repeated unchanging observations.

Server-side delegation bounds must serialize concurrent attempts and count the whole task family, preventing recursive fan-out. Existing permission checks and durable operation receipts remain authoritative. Waiting for children must not cause extra model polling.

Recurring work uses durable usage after its last completed cycle, not lifetime counters, for cycle budgets. Finite work retains lifetime budgets. A rolling budget prevents short cadences from spending indefinitely across many successful cycles. Limits are application admission checks; unknown provider usage and in-flight calls are reported honestly, and provider-side hard budgets remain recommended.

## Usability and acceptance

Expose clear next actions for missing provider, stopped runtime, exhausted budget and pending approvals. Supply useful runnable recipes with measurable deliverables and finite/recurring variants. Do not add tools merely to increase their count; reuse the extensible capability system.

Tests must prove small-task routing, bounded fan-out under concurrency, recurring budget boundaries/restart behavior, idle zero-call behavior, preserved permissions and a fresh-install journey. Verify source/types/build/browser/security/platform gates on the final revision. Record actual provider and installation evidence separately from simulated tests. Publish a stable release only when its stated acceptance gates pass; never relabel alpha to conceal unverified requirements or promise viral adoption.
