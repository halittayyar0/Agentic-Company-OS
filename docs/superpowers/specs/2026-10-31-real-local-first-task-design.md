# Repeatable genuine local first-task proof

The current release depends on a maintainer computer having enough free memory
for a cold model download and genuine first task. The accepted host margin is
6 GiB free virtual memory; repeated shortages have prevented the remaining
current-source case. Some old temporary host fixtures are also unavailable.
Retained source-bound reports must not be relabeled as fresh evidence.

Add an explicit, repeatable proof on the standard public GitHub Windows runner.
This uses the same application installer, real PostgreSQL, seven-language
application, actual local Ollama model preparation UI and first-task path. The
synthetic brief requests `calculate(58.5 + 14.5)` and completion of one task.
Only calculate, tool discovery and completion are allowed; no agent creation,
delegation, paid provider or cloud fallback is permitted. A bounded relay records
unmodified model requests and responses privately and independently checks the
calculator result, actual usage and agent completion.

Pin complete official Ollama 0.40.3 Windows and PostgreSQL 17.11 archive bytes.
Start in a new owned model home without inherited provider credentials. Download
the curated `qwen3.5:2b-q4_K_M` model through the app, then independently verify
every downloaded blob against the anonymous registry manifest. Keep the original
12-call cap, 20-minute transfer deadline, 15-minute task deadline and four-minute
per-inference deadline. Never retry an uncertain task or inference.

The result must include actual commit/tree, one model download, positive settled
usage, exact arithmetic tool evidence, one completed task with agent authority,
zero fallbacks and unchanged agent count. Capture the actual saved delivery
result in the visible viewport at 320 and 1024 pixels. The number in the original
brief cannot satisfy this assertion. Scroll the existing delivery section inside
the application's real scroll container and capture the viewport; a full-page
image does not scroll desktop containers. Always stop the owned processes. A
failed cleanup fails acceptance.

Upload only a deliberately constructed public receipt and synthetic screenshots;
never upload a raw home, database, model, token, request, response or process log.
The receipt must not echo exception text or absolute host paths. Preserve failed
runs. This is finite Windows first-use evidence, not physical-device, other-OS,
general model-quality or 24-hour acceptance.

Run the new proof for changes to its own workflow/helpers and on explicit release
dispatch. Use only the standard `windows-2025` runner with read-only repository
permissions and immutable Node-24 action pins. No new provider credentials or
paid services are needed. Existing release checks remain mandatory; new evidence
belongs to its actual tested commit. Do not publish the stalled older source by
borrowing a newer source's proof.

Routine implementation choices are delegated by the user's continuous goal.
This change adds repeatable release evidence, without changing application UI,
backend permissions or agent execution policy.
