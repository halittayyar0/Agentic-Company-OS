# Resume a workspace when its private phone network is offline

A saved private-network phone preference currently makes `readInstallation` and the executor reject the whole workspace when Tailscale is missing or disconnected. A temporary optional network outage must not prevent work on the computer.

For an existing installation only, retain the selected plan and all credentials, budgets, permissions, database and preferences. Validate all ordinary runtime prerequisites. If the private phone preflight cannot establish a safe owned connection, launch the ordinary local-only deployment: native loopback bind and remote access disabled; container host publishing remains loopback while its API retains the required internal container interface. Both keep only local trusted hosts/origins. Never configure Serve, use Funnel, change a firewall or send credentials to a guessed hostname in this fallback. Return the closed `phoneUnavailable: true` signal; never include native probe output or errors in that signal. The next ordinary restart retries the saved private-network preference. Fresh installation remains strict.

Show the verified local workspace link and a seven-language explanation: phone access is unavailable; the workspace is available on this computer; connect Tailscale and restart the launcher to retry. Retain the saved language, RTL and keyboard behavior. Use the existing loopback setup status page and its authenticated operator-key reveal. A resumed status session cannot create/reinstall a workspace. Reopening the original private link restores this status; a plain browser refresh after the fragment is removed still requires that link, as the existing no-browser-storage security contract requires. No application API, agent, inference or paid service is needed for the status view.

Approaches considered: failing the whole resume preserves today's outage; silently changing the saved preference loses intent; a local-only runtime with an explicit status view preserves intent and useful work. The last is the implementation choice delegated by the user, who explicitly opted out of further routine approval questions. This fixes offline resumption, not post-install phone preference management.

The existing source/portable/native entry points share the executor. Native startup opens the status view only for this degraded result; source and portable launchers print the same private local status link. The frozen C47 release candidate and original evidence remain unchanged on their own branch. New platform/runtime proof and protected integration remain required for this new branch.
