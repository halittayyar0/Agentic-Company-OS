# Built-in tools and skills

User authorization: extend Agentic Company OS with a broad set of useful tools
and skills. Proceed with the balanced research, software, documents/data, and
operations option; no answer to the optional weighting question is required.

## Product contract

- Add 30 versioned, first-party skill recipes in five groups. Each has required
  inputs, a concrete deliverable, procedure, checks, and tool requirements.
- Add ten agent tools: discover/read skills, arithmetic, text statistics, text
  comparison, JSON inspection, CSV profiling, date conversion, URL inspection,
  and SHA-256 text fingerprinting. Tools operate on bounded supplied data, with
  no new network, filesystem, shell, credential, or paid-service capability.
- Keep existing browser/file tools as the means of collecting real evidence.
  Skills do not grant permissions, install packages, or claim outcomes.
- Add an authenticated, read-only catalog API and a searchable `/skills` page.
  Native details controls expose requirements and steps. A deliberate action
  creates a reviewable project draft; ordinary project submission starts work.
- Catalog, procedures, labels, errors, and draft text support all seven locales.
  Source values and tool identifiers remain literal evidence.
- Use the existing dispatch, active-agent, emergency-stop, lease, exclusive-turn,
  durable receipt, and untrusted-output boundaries. New tools are read-only.
- No schema migration, new third-party dependency, or service subscription.

## Implementation and verification

1. Reproduce missing bounded utility behavior with focused tests; implement
   strict schemas and bounded deterministic processors (no eval or shell).
2. Author and validate the versioned seven-language skill catalog; every
   referenced tool must exist and every skill must have meaningful checks.
3. Connect tools to the production catalog/dispatcher/receipts. Test actual
   dispatch rejection, emergency stop, inactive agents, and durable execution.
4. Describe the catalog API in OpenAPI, regenerate clients, and verify the
   authenticated route and locale validation.
5. Implement the searchable, keyboard-accessible phone/desktop library and
   explicit project-draft handoff. Verify all languages including Arabic RTL,
   loading/error/empty states, permissions disclosure, and no premature writes.
6. Run typecheck/build/budget and focused browser/source checks. Record exact
   results. The broader Goal 7 release gates remain active.

Design thesis: a compact work library, organized by the result people need.
Use existing semantic colors, readable lists, visible input labels, 44px touch
targets, and progressive disclosure; avoid a dashboard of decorative metrics.
